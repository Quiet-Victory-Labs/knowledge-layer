# Local qualification runbook

These commands exercise the **synthetic loopback Compose profile**. They do not certify a cloud connector or a production deployment. Run from the repository root with `.env` generated by `python scripts/init_env.py` and the two services healthy.

```sh
docker compose up --build -d --wait
uv run --no-sync python scripts/drill_postgres_recovery.py
uv run --no-sync python scripts/drill_schema_migrations.py
uv run --no-sync python scripts/drill_refresh_jobs.py
uv run --no-sync python scripts/drill_postgres_connector.py
uv run --no-sync python scripts/drill_local_gateway.py
uv run --no-sync python scripts/evaluate_quick_agent.py
uv run --no-sync python scripts/benchmark_source_paging.py
uv run --no-sync python scripts/drill_postgres_batch_projection.py
uv run --no-sync python scripts/drill_postgres_document_search.py
```

The recovery script makes a custom PostgreSQL dump, restores into a disposable database, compares all Knowledge Layer table counts and streamed content fingerprints plus the recorded schema revision, and drops the disposable database. Fingerprints sort per-row SHA-256 digests with an 8 MB server sort budget and read 64 KiB client blocks, avoiding a whole-payload aggregation memory spike. It removes the dump after a pass unless `--keep-backup` is supplied. The schema drill checks fresh upgrade, exact legacy adoption, drift refusal, startup gating, a private governance audit export, and the proposal-archive versus first-publication race in disposable databases. The refresh job drill queues work, exits the submitting process, and verifies a separate worker container wrote the snapshot. The connector script creates and drops a temporary database and restricted role; it tests grant visibility, schema drift, password rotation, and revocation. The gateway script sends 100 read-only MCP calls with eight workers and checks denial of missing or invalid credentials. The paging benchmark creates and drops a separate synthetic PostgreSQL database with 20,000 connections and 5,000 reader grants, comparing query plans before and after the seek index. The batch projection drill creates a disposable migrated PostgreSQL database with 50 source snapshots, checks bounded list-path SQL statements and exact parity with single-source responses, then drops the database. The cross-source search drill creates 20,000 synthetic sources, snapshots, and concepts with 5,001 reader grants; it verifies an older authorized citation and concept are found, an ungranted match is hidden, and semantic candidate selection stays bounded. It runs `ANALYZE` after bulk loading and drops its disposable database. These are local SQL and functional checks, not end-to-end production latency or an SLO. All reports are written under ignored `.local/`; the drill reports are owner-only files.

For an enterprise pilot, use a customer-managed backup policy and real restore target. Do not use the demo `.env`, bearer token, or synthetic three-source measurements as evidence of customer identity, ACL propagation, warehouse certification, or production recovery objectives. The dated [enterprise readiness drill](enterprise-readiness-drill-2026-10-02.md) records the latest observed local result and remaining gates.

For recurrence and citations, provision a disposable PostgreSQL registry and a [synthetic adapter](../examples/reference_adapter.py), then follow the [validation plan](refresh-and-citations-2026-10-03.md). Upgrade a backed-up older schema, drive HTTP/MCP and a separate worker, and verify injected failures and permission denials. For a task-owned Docker PostgreSQL container, recovery accepts `KNOWLEDGE_RECOVERY_CONTAINER`, `KNOWLEDGE_RECOVERY_USER` and `KNOWLEDGE_RECOVERY_DATABASE`; defaults use Compose. Keep passwords in protected references and reports/backups private. Stop only task-owned services and drop the temporary database after recovery readback. This does not replace customer deployment, IdP, connector or recovery qualification.

For [company guidance](company-guidance.md), provision a fresh PostgreSQL registry whose name starts with `knowledge_guidance_drill`, with owner-only `DATABASE_URL_FILE` and `KNOWLEDGE_AGENT_TOKEN_FILE` references. The dedicated guidance drill checks migration, preservation, conflicts, withdrawal, concurrent edits and recovery using a procedural template and bundled Northstar synthetic data. The [public template](../examples/company-guidance-synthetic.json) uses `synthetic-analytics` scope and contains no source bindings or customer records. Capture private receipts, verify recovery, then stop task-owned resources. This does not establish native client activation, a live customer IdP or analytical outcomes.
