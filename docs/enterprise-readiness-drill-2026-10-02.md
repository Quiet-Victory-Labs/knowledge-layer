## Enterprise gates still open

1. **Authorization:** The OIDC pilot is explicitly one organization and requires explicit grants on connection records. The original scan found missing authorization for an underlying source selector. A subsequent local remediation added an operator-owned manifest of exact source identities and allowed subjects/groups. OIDC creation, same-name agent retries, configuration updates, queue submission, and worker refresh now enforce it; identity changes require a new connection and grants. Local tests cover denied folders, file patterns, credential references, Iceberg namespaces, and withdrawn approvals. Field-level filtering and source-native row/document ACL mirroring remain open. Verify the new boundary through a real IdP and restricted source before a customer pilot.
2. **Durability:** The OIDC pilot now has a bounded PostgreSQL job queue and separate worker; the demo still refreshes synchronously. The local worker and restore drills are small-data functional proofs. Customer-like upgrade, worker-loss, multi-worker overlap, load, monitoring, and backup/restore objectives with measured RPO/RTO remain before production use. Job execution is at least once.
3. **Identity:** Local tests and a disposable real Keycloak/PostgreSQL drill cover signed JWT, issuer, audience, expiry, scope, group, browser login/local logout, and fresh role-change behavior. The Keycloak drill observed that an already issued JWT retains its old group until token expiry. The new browser session cap defaults to 15 minutes or the shorter ID-token expiry. A customer's IdP, deployed HTTPS endpoint, upstream SSO logout, revoked-user response, and claim mapping still need qualification.
4. **Connectors:** PostgreSQL passed a local restricted-grant qualification. Snowflake, BigQuery, Redshift, and other SQL dialects remain generic adapters until tested against real accounts with restricted roles, credential rotation, drift, denied metadata, and driver version locks. A displayed connector option is not a vendor certification.
5. **Scale and model cost:** The 100-call loopback measurement used only three sources and no agent model. Pagination traversed 52 synthetic sources; a separate 20,000-row SQL benchmark verified the v8 seek index, the 50-source PostgreSQL drill verified batched response parity, and the dense 20,000-snapshot concept-search drill verified v9 backfill, grants, and bounded lexical candidates. These did not measure end-to-end concurrent API latency, source-read log delivery volume, full-snapshot memory use, or actual model cost. Semantic ranking is bounded to the top 256 lexical candidates, so semantic-only recall outside that set remains unqualified; curation work still builds a cross-source concept list. Externally cited evidence can add reads per assertion. Run representative source counts, payload/latency budgets, and real model token/call accounting before setting SLOs. Optional decision providers need held-out, steward-labeled false-skip and calibration evaluation before gate mode.

GitHub Code Security and Secret Protection are disabled; a monitored public security contact and independent legal license review remain open. The local signature scan and zero-vulnerability results are point-in-time checks, not a publication approval.

Customer-defined retention, independent immutable delivery, loss monitoring, complete deployed-path attribution, representative publication criteria, field-level policy, and source-native ACL inheritance remain unqualified.
