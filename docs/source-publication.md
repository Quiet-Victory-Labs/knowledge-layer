# Publishing a source for agent use

Discovery and model proposals are drafts. A connector cannot set `agent_ready` or `meaning_certified`, even if its payload says `ready`. The service derives `agent_ready` from a steward publication record pinned to the current snapshot version. Publication does **not** certify every candidate concept, metric, or join: agents still receive each assertion's trust state and must treat candidate claims as drafts.

The browser's selected-source panel shows publication blockers and, for stewards, a publication or withdrawal action. The read-only preview is `GET /api/knowledge/connections/{id}/publication`. To publish, a steward with a `manage` source grant sends `POST` to that route with `expected_snapshot_id`, `expected_snapshot_version`, and a 16–1000 character rationale. The version check prevents an approval from landing on a source that changed after review. `POST /api/knowledge/connections/{id}/publication/withdraw` requires an 8–1000 character reason. OIDC browser requests also require the CSRF token. Agents may read the resulting status through existing API and MCP source summaries; they cannot publish through the agent API or MCP.

The current gate requires complete discovery, at least one asset and evidence record, no discovery errors, no stale approved assertion, no active refresh, and at least one effective owner-approved assertion recorded in the decision ledger. Pending candidates may remain visible, with candidate trust labels; the steward's rationale should state the permitted use. A configuration change, refresh, source error, active refresh, or stale supporting document suspends `agent_ready`. A new snapshot requires a new publication. Withdrawal remains possible while a current publication is suspended. Historical snapshot reads never claim current agent readiness.

Archiving any local proposal withdraws an active publication for the current version, because the visible source context changes. The steward must refresh, review, and publish a new snapshot to restore agent readiness; the withdrawn version cannot be republished. Publication rechecks eligibility after taking the source lock, so an archive between preview and commit cannot leave a source agent-ready without the reviewed assertion.

Revision `0004_source_publications` stores the publishing actor, rationale, snapshot version, time, and later withdrawal. This is a narrow source-level release gate. Field-level entitlement propagation, source-native ACL mirroring, and a formal enterprise audit retention policy remain open.

Revision `0005_decision_digests` also binds each owner decision to the proposal content and cited evidence that the owner reviewed. If an adapter reuses an approved proposal ID with changed content or evidence, the decision becomes `stale_review` and cannot support publication. Existing decisions from before v5 have no binding and require explicit re-review. A source-supplied proposal cannot shadow a locally stored proposal with the same ID.
