# Get help

Start with [your first reviewed knowledge](docs/getting-started.md), the
[self-hosting guide](docs/self-host.md) or the
[documentation index](docs/README.md). Knowledge Layer is a public source alpha;
support and compatibility depend on the documented profile and scope.

## Usage questions

Ask in [GitHub Discussions](https://github.com/Quiet-Victory-Labs/knowledge-layer/discussions)
for installation, agent setup, semantic modeling or workflow questions. Describe
what you are trying to do and the step where you need help. Use a small synthetic
example when a source or definition matters.

## Bugs and feature requests

Use the [issue templates](https://github.com/Quiet-Victory-Labs/knowledge-layer/issues/new/choose)
for reproducible bugs, feature proposals and connector requests. Search existing
issues first. Include the version or commit, deployment profile, expected and
actual behavior, and steps with synthetic inputs. For installation problems,
include the relevant `./knowledge-layer doctor` result and reviewed logs with
credentials and private details removed.

A connector request should state the source/version, required scope and the
permission boundary. An available adapter or passing offline fixture does not
establish native vendor-account qualification. Check the
[capability matrix](docs/capability-support-matrix.md) before relying on a path.

## Security reports

Report vulnerabilities through
[GitHub private vulnerability reporting](https://github.com/Quiet-Victory-Labs/knowledge-layer/security/advisories/new)
and follow [SECURITY.md](SECURITY.md). Keep vulnerability details out of public
issues and discussions. Do not post credentials, source records, private
documents or customer metadata in any public support request.

Maintainer support has no guaranteed response time or production service-level
agreement. If you have a documentation improvement or a reproducible fix, the
[contribution guide](CONTRIBUTING.md) explains how to help.
